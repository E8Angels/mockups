- 2026-05-22 — jordan — Major restructure to Entity ⇄ Opportunity model. An entity (org/individual) now has 0..N opportunities (grant cycles, sponsorship terms, one-off gifts). The 7-stage pipeline lives on the opportunity, not the entity, so Walton 2025 (declined) and Walton 2026 (in conversation) coexist as two cards. Renamed module from "Sponsor CRM" to "Development CRM"; folder `sponsor-crm/` → `development-crm/`; all tables `sponsor_*` → `development_*`; URLs `/admin/sponsors` → `/admin/development`; canonical role `SponsorManager` → `DevelopmentManager`; resource keys `admin.sponsors.*` → `admin.development.*`. New tables: `development_entities`, `development_opportunities`, `development_opportunity_owners`, `development_opportunity_attachments`, `development_opportunity_email_links`. Notes and follow-ups are polymorphic (`parent_kind` + `parent_id`); email events are entity-scoped with optional opportunity tags.
- 2026-05-22 — jordan — Role tags reworked: system-managed `Sponsor` / `Sponsor Prospect` / `Past Sponsor` / `Funder` derive from opportunity state per entity. Sponsor temporal logic uses `term_end_on` to flip Sponsor → Past Sponsor. Funder has no temporal split — any grant relationship qualifies.
- 2026-05-22 — jordan — Mockup pages: new `entity-detail.html` (relationship view: contacts, owners, durable attachments, opportunities table, cross-cycle activity timeline). Renamed `sponsor-detail.html` → `opportunity-detail.html` and redesigned around a single opportunity (entity context strip, opp-scoped facts, reporting status row, Add-a-note scope toggle, opportunity-scoped Activity feed with optional `+ Show entity activity`). Staff dashboard and board dashboard rebuilt around opportunity Kanban with opportunity-name (primary) + entity-name (secondary) tiles, opp-type chips, and an Entities directory view.
- 2026-05-22 — jordan — Opportunity type model: opportunities have a `type` (`grant` | `sponsorship` | `gift`) with an optional `subtype` valid only for sponsorships (`annual` | `event` | `other`). Filter rail and chips collapse to 5 flat labels for the user (Grant / Annual Sponsorship / Event Sponsorship / Other Sponsorship / Gift). In-kind is no longer an opportunity type — `development_amounts` gains a `nature` column (`cash` | `in_kind`) and `in_kind_description`, so a single opportunity can mix cash and in-kind rows ($10,000 + a case of wine valued at $750).
- 2026-05-22 — jordan — New Opportunity dialog's Ask amount field becomes a multi-line editor: each line has a Cash/In-kind segmented control, currency input, inline description (revealed for in-kind), and a remove affordance. `+ Add another line` adds rows. Subtotal helper shows cash/in-kind breakdown when 2+ lines. Submission writes one `development_amounts` row per line. Resolves the open item asking whether in-kind ask should be collectible at create time.
- 2026-05-22 — jordan — Type tags collapse from 5 → 3: top-level chips/filters are now `Grant / Sponsorship / Gift`.
